# Claude's notes

LLM-written. This is Claude's running record of the design: what's been decided, where it came from, and what's still open. The team's own descriptions live in the human-authored files (`overview.md`, the architecture docs, `specs/`), which take precedence over anything here.

## Sources
- **Muscle Map — Project Setup Guide** (team doc, Nov 3, 2026): stack, repo layout, Google Cloud setup, data model, first endpoints, iOS setup, required course files, setup checklist.
- **Lift Tab UI** (team mockups): the four Lift screens and the design tokens.

These two documents aren't in the repo. Their content is summarized in `server_architecture.llm.md` (data model, server), `client_architecture.llm.md` (app, design tokens) and `API.md` (endpoints).

## Decisions
| Decision | Source |
|---|---|
| Stack: SwiftUI app (iOS 17+), Flask on App Engine (Python 3.13), Firestore in Datastore mode via `google-cloud-datastore` | Setup guide |
| The app never talks to the database and doesn't use the Firebase SDK; everything goes through the Flask API | Setup guide (course requirement) |
| One repo: `ios/`, `server/`, `shared/`, course docs at the root | Setup guide |
| Four tabs, each with icon and label: Home, Lift, Goals, Camera. Only Lift is built for real first; Camera is behind a feature flag, hidden from testers | Setup guide |
| The Exercise library tile is dropped: exercise search lives in Create workout, per-exercise records in History (on Home) | Setup guide |
| "Custom plan" is a disabled tile marked "Soon" until multi-week programs are designed | Setup guide |
| Region `us-west2` for App Engine and the database (both permanent) | Setup guide |
| Sign-in by SMS code, adapted from the course's SMS authentication example | Setup guide |
| Store sets; compute style, e1RM, volume, muscle levels and goal progress on request | Setup guide |
| Weights stored in kg | Setup guide |
| The active workout lives on the phone (SwiftData) and is sent once on Finish | Setup guide |
| Dark mode only | Setup guide (`.preferredColorScheme(.dark)`), Lift Tab UI |
| Workflow: spec → approved plan → scaffold → tests → build → review → PR; humans approve the plan and merge | Team setup session, Nov 3, 2026 |
| Design tokens: the Lift Tab UI set (`background`, `surface`, `surfaceRaised`, `sheet`, `accent`, `onAccent`, `textPrimary`, `textSecondary`, `intensity` 0–4), plus `border`, which has the same value as `surfaceRaised` for now so borders can change on their own. The setup guide's `surfaceBorder` name is dropped | Sasa, Nov 3, 2026 |
| Muscles are tracked at head level (`triceps_long`), each with a `parent` muscle (`triceps`) and a `group` (`arms`), so the Home body map can shade small regions while chips and filters roll up. Start with about 45 heads. IDs are stable: new muscles are only ever added, never renamed or reused. An exercise may point at a parent ID, which spreads its weight evenly across that muscle's heads | Sasa, Nov 3, 2026 |
| Muscle head IDs are parent first, then a short head name: `delts_rear`, `triceps_long`, `glutes_max`, `quads_vastus_lateralis`. Every head of a muscle sorts together and its parent is readable from the ID. Enforced by `server/tests/test_muscles_json.py` | Sasa, Nov 3, 2026 |
| The muscle list isn't limited to what the body map can show. The map starts as a 2D drawing, and mapping IDs to its regions is the Home tab's job, not part of `shared/muscles.json`. A muscle with no region of its own still counts, and can appear in a detailed list view later | Sasa, Nov 3, 2026 |
| "UP NEXT" on Lift home, without a plan: the saved workout done longest ago among those done before (`Template.last_done_at` not null). Never-done ones are never UP NEXT, and there is no UP NEXT until at least 2 have been done. Cards: UP NEXT first, then newest-created first. A saved workout made with "Save as a workout" counts as done (its `last_done_at` = the workout's `started_at`). With a plan (later "Custom plan" feature), UP NEXT follows the plan's order. Replaces the Nov 3 rule (never-done first) | Sasa, Nov 4, 2026 |
| Saved workout (Template) IDs are UUIDs made on the phone, like workouts and sets, so saving is safe to retry | Sasa, Nov 3, 2026 |
| Muscle chips on a saved-workout card: the 3 parent muscles (not heads) the workout works most, summed over its exercises' target sets × muscle weights, each shaded by its share of that work (intensity 0–4). Computed by the server and returned with `GET /templates`. Heads only matter for the body map | Sasa, Nov 3, 2026 |
| API conventions: lists wrapped in an object; six error codes (`bad_request`, `unauthorized`, `forbidden`, `not_found`, `conflict`, `internal`); a repeated `POST /workouts` returns `200` with the same body (first time `201`); `PUT /users/me` is a partial update | Sasa, Nov 3, 2026 |
| `POST /workouts` body = the guide's example plus phone-made `id`s on the workout and each set, `timezone` and `local_date`, as the guide's data model requires | Sasa, Nov 3, 2026 |
| Weights are stored as the exact kg conversion, never rounded (157.5 lb → 71.4408 kg); the app rounds only for display, so values round-trip exactly | Sasa, Nov 3, 2026 |
| The plate loader supports both lb (45 lb bar; 45, 35, 25, 10, 5, 2.5) and kg (20 kg bar; 25, 20, 15, 10, 5, 2.5, 1.25), with a kg/lb toggle. lb is the expected default. Details (whether the toggle also changes the profile's units) go in the Lift set-entry spec | Sasa, Nov 3, 2026 |
| **Pending team agreement:** dumbbell sets log one dumbbell's weight ("the 50s" = 50). Each exercise has `implement_count` (1 or 2), and volume multiplies by it | Sasa (proposed to the team), Nov 3, 2026 |
| iOS logic lives in a local Swift package, `ios/MuscleMapKit/`, from day one: one module per area (`Models`, `Networking`, `LiftCore`; later `HomeCore`, `GoalsCore`), each with its own test target, run with `swift test` without the simulator. The app target holds only views and wiring. This replaces the setup guide's `ios/MuscleMap/Models/` and `Networking/` folders | Sasa, Nov 3, 2026 |
| **Sign-in (kept minimal; the professor doesn't want time spent on auth):** our server passes `/auth/sms/start` and `/verify` through to the course's hosted SMS service (`ecs191-sms-authentication.uc.r.appspot.com`), so there's no Twilio account of our own. On success our server creates its own session for the course `user_id`; `@require_user` then checks only our database. The course `app_token` stays on the server (needed only for real phone numbers; the test number `+15305550000` / `123456` works without it). Sessions never expire for now; logout comes later. Development uses the test number | Sasa, Nov 3, 2026 |
| Home's history must reach any point in time: `GET /workouts` gets a `before=<timestamp>` parameter when Home is built, and the muscle map will need an end date as well as a window | Sasa, Nov 3, 2026 |
| Workouts keep a `status` on the server. For now the app only sends finished workouts, so the server always stores `finished`; `active` is for when sets are saved live later | Sasa, Nov 3, 2026 |
| Exercise search: `GET /exercises` is public and takes `q` and `group`. A match is any word start (after a space or hyphen) in the name or an alias; order is name-starts, then later word, then alias-only, ties A–Z. Full details in `specs/exercise-search.llm.md` | Sasa, Nov 3, 2026 |
| An exercise belongs to every group of its primary-role muscles (Deadlift is in Legs and Back). The server returns `groups` and `primary_muscles` (parent display names, strongest first) on each exercise | Sasa, Nov 3, 2026 |
| App Engine uploads only `server/`, so the server reads its own copy, `server/muscles.json`. A test fails if it differs from `shared/muscles.json`; edit `shared/` and copy it over | Sasa, Nov 3, 2026 |
| The local server runs on port 5001, not 5000: on recent Macs the AirPlay Receiver holds 5000. Debug builds call `http://localhost:5001` | Sasa, Nov 3, 2026 |
| Picker texts: "Can't reach the server." with "Try again", "Search exercises", "Picked exercises" (temporary list), "Last: 2 days ago" when there's no last set | Sasa, Nov 3, 2026 |
| Workflow: planning (spec, plan, contract) happens in the main folder and lands as a small planning PR first; features then build in lanes (`scripts/lane.sh`, `../ecs191-impl-<n>`), each with its own emulator port. Merge order follows dependencies (picker → log a workout → saved workouts) | Sasa, Nov 3, 2026 |
| Logging a workout (#42): 22 decisions in `specs/log-workout.llm.md` → "Decided". Key ones: `POST /workouts` saves the workout, its sets and each exercise's history (`UserExercise`) in one transaction; daily and running totals come later with Home/Goals; Debug builds sign in with the course test number on launch; one open workout at a time (Resume card); logged sets can be edited and deleted; the lb/kg switch changes the whole app; dumbbells log one dumbbell's weight (team still to confirm) | Sasa, Nov 3, 2026 |
| Saved workouts (#43): 19 decisions in `specs/saved-workouts.llm.md` → "Decided". Key ones: `top_muscles` items get a display `name`; template IDs are phone-made UUIDs in all examples; the top chip is always the darkest; a saved workout can be made from a finished one ("Save as a workout" sheet), with targets taken from what was done; rename and delete by long-press; UP NEXT moves right after Finish | Sasa, Nov 3, 2026 |
| Effort battery uses traffic-light colors: green under 80 %, yellow 80–89 %, red from 90 % (near failure and failure, also the flame). Tokens `effortLow` `#4CC38A`, `effortMid` `#F2C94C`, `effortHigh` `#E5484D` in `Theme.swift`; the rule is `EffortLevel` in LiftCore. On a selected effort chip the icon uses `onAccent` (#63). Claude proposed the thresholds and colors | Sasa approved, Nov 4, 2026 |
| Saved-workout cards have two lines (#63): line 1 the name (bold, one line, "…"), the exercise count "3x" and the last done time on the right (`today`, `1d ago`…`13d ago`, `2w ago`…`8w ago`, then `2mo ago` and up; calendar days; nothing when never done; `lastDoneShort`); line 2 the muscle chips (as many as fit) and Start. No focus on the card; the header is "SAVED WORKOUTS" without a count. The UP NEXT card keeps its badge on line 1, between "3x" and the time, plus the accent border and Start | Sasa, Nov 4, 2026 |
| Set log badges (#63): a drop set shows "D" and, like an F set, still takes a number, so the badges read "1, D, 3". The number is the set's place in the workout | Sasa, Nov 4, 2026 |
| Lift feedback (#67): 15 decisions in `specs/lift-feedback.llm.md` → "Decided". Key ones: a 10-second countdown (beep each second, long beep at 0, taps while open); when closed or locked, local notifications play the same countdown from the time left (10 sound files made by our own script), Time Sensitive; beeps mix over music with no ducking and the silent switch mutes them; "Save as a workout" keeps every exercise (unlogged: 3 sets, 90 s); a changed workout from a saved one asks "Update '<name>' with your changes?" (changed = added exercises, more sets or different reps; fewer sets and rest don't count) | Sasa, Nov 4, 2026 |
| **Body tab** (between Home and Lift): the MuscleLab page from Aaradhya's prototype (anatomy figure, Stats and Muscle Map views, insight cards). Logic in a new `MuscleMapKit` module, `BodyCore` (muscle IDs, SVG figure art as package resources, workout analysis, page model), views in `ios/MuscleMap/Features/Body/`. Still reads the prototype's bundled sample sessions (Oct 20 – Nov 2, 2026); no server calls yet | Aaradhya, Nov 3, 2026 |
| Body tab styling: `BodyTheme` and `StatsStyle` (shape in `DesignSystem/Body/`, values in `DesignSystem/Theme.swift`). Values the app already has (background, surface, sheet, border, text colors, accent, onAccent, card radius 16, border width, spacing) come from `Theme`; the figure, ring and chart tokens are Body-only | Aaradhya, Nov 3, 2026 |
